## O que ficou de fora e por quê

- **Modal de identificação obrigatório** (`js/api.js`, `carregarIdentificacao`): mantido como está por decisão do autor. **Proposta:** passar `data-obrigatorio="false"` no catálogo para o visitante ver as ferramentas antes do modal, e medir o abandono (issue I4 do diagnóstico).
- **Hospedagens fora do `sitemap.xml`** (88 URLs; deveriam ser 99): o arquivo é gerado pela API em `learntech-content/scripts/gerar-sitemaps.mjs`, que só lê `ferramentas.json`. Não foi editado aqui; será corrigido na API (issue I1). O `verificar.ps1` agora avisa enquanto a contagem não bater.
- **Cópias geradas** (`data/tools.js`, `data/host.js`): não editadas; vêm do `npm run copias` da API.
- **CSP por `<meta>`** (T6): risco médio (Turnstile, redirecionamento dos favicons do Google para `t*.gstatic.com`, script de tema inline que pede hash). Precisa de teste do fluxo completo do SDK no navegador antes de publicar; fica para uma leva própria.
- **`404.html`** (T6): não criado nesta leva, para manter o escopo no plano prioritário; é independente e pode entrar junto com a CSP.
- **"Carregar mais" anexando só os cards novos** e o `innerHTML` fixo de `desenharVazio`: não estavam no plano de ação (estão na I6 e na seção de segurança como melhoria); não mexi.
- **Re-render na resposta tardia**: quando a API chega depois de 1,5 s, a grade é redesenhada uma vez (a animação de entrada repete e, se o foco estiver num card, ele se perde). Aceitável para o caso raro; se incomodar, dá para trocar só os `href` dos cards.
- **`docs/claudeia/05-testes-manuais.md`** ainda cita 45 ferramentas e 10 hospedagens: é o roteiro de uma rodada anterior; não reescrevi.
- **`docs/claudeia/diagnostico-mvp-2026-11-03.md`**: já estava no diretório sem rastreamento quando comecei; não foi tocado.
